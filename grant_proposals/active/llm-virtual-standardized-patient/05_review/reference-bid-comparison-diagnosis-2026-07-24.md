# 参考标书对照诊断

日期：2026-07-24

参考材料：`07_references/pdfs/寇任重-南京市中医院-“枕项部埋线法”治疗无先兆偏头痛的临床研究及脑fMRI机制研究.pdf`

本次只参考其申报书结构、表述颗粒度和章节职能分配；其预实验部分不作为本项目写作依据。

## 总体判断

当前 V4 稿的主要问题不是方向错，而是“各部分职能没有拉开”。立项依据、研究现状、研究目标、研究内容、研究方法、创新点、可行性和预期成果反复围绕同一组词展开：护理本科生、护患沟通与健康评估、4 个案例、案例蓝图、专家审核、学生自评、教师评分、对话日志、开放反馈。

这些词本身是对的，但现在处处都出现，导致评审读完后容易只记住“要做一个 LLM 虚拟标准化病人”，却不清楚：

- 到底解决哪一个教学痛点。
- 到底建设哪几个具体训练场景。
- 到底如何让模型不乱说。
- 到底如何评价学生表现。
- 到底哪些是成果，哪些是过程，哪些是质量控制。

参考标书的可取之处在于：一句核心问题反复出现，但每个章节只承担自己的任务。立项依据解释为什么做；研究目标只写要明确什么；研究内容拆成疗效与机制两条；方法细到对象、分组、干预、指标、时间点、统计；进度对应阶段产出；条件部分列团队和设备基础。它不是不重复主题，而是不重复同一层级的信息。

## 我们标书的具体问题

### 1. 立项依据过长，且把后文方法提前说完

V4 第一部分已经写了案例蓝图、知识约束、专家审核、教师评分、对话日志、开放反馈、伦理治理。第二、三、五部分又重复这些内容。

建议：立项依据只保留四层逻辑：

1. 护理学生在护患沟通与健康评估训练中缺少可重复、可反馈的情境训练。
2. 传统标准化病人资源有限，纸质案例又不能连续互动。
3. LLM 虚拟病人可补足互动训练，但存在事实漂移、错误反馈、隐私和教师责任问题。
4. 因此本课题要构建“教师监督下、案例约束下、可评价”的护理虚拟标准化病人。

不要在立项依据中提前展开完整案例字段、日志指标、评分维度和进度安排。

### 2. 研究目标应更短，现在像研究内容

参考标书目标很短，只写两条“明确什么”。我们现在的研究目标写成了四段，已经包含案例建设、系统建设、质量控制和教学评价。

建议改为 3 条目标：

1. 构建适用于护患沟通与健康评估训练的护理虚拟标准化病人案例蓝图和首批案例。
2. 建立基于大语言模型的虚拟患者交互与反馈原型，并形成专家审核和教师监管流程。
3. 评价该训练方案在护理本科生教学应用中的可用性、反馈质量和初步教学效果。

目标部分不解释为什么、不展开怎么做。

### 3. 研究内容要按“任务包”写，而不是按概念反复解释

当前“研究内容”里案例库、蓝图、系统、评价都写得有道理，但语言仍偏解释性，缺少任务边界。

建议拆成 4 个研究内容：

1. 护理训练场景与案例蓝图构建：确定课程环节、训练能力、4 类案例和蓝图字段。
2. 虚拟标准化病人原型构建：形成案例输入、角色扮演、信息披露、反馈生成和日志记录流程。
3. 专家审核与可用性测试：审核病例真实性、护理适切性、反馈准确性和安全边界。
4. 教学应用与效果评价：在指定课程/班级中收集学生自评、教师评分、日志指标和开放反馈。

每个内容后面只写“做什么、产出什么”，不要又写一遍立项意义。

### 4. 研究方法需要详细，当前详细度还不够硬

这是现在最需要补的地方。参考标书在方法部分很具体：病例来源、样本量、纳排标准、随机/盲法、干预方案、观察指标、时间点、统计方法都写得清楚。

我们的标书目前说了“同一课程内前后测+教师评分+日志分析+开放反馈”，但缺：

- 依托课程名称。
- 学生年级、班级、人数。
- 是否有对照组或仅前后测。
- 干预次数、每次训练时长、每名学生完成几个案例。
- 训练前测和后测分别测什么。
- 教师评分表维度和分值结构。
- 日志指标的定义。
- 开放反馈或访谈如何收集、如何分析。
- 统计方法。

建议方法部分必须补成“执行方案”，例如：

- 对象：某年级护理本科生，预计 n 人 `[VERIFY]`。
- 分组：若有平行班，设常规教学组与虚拟标准化病人训练组；若无平行班，采用单组前后测 `[VERIFY]`。
- 干预：4 个案例，每名学生完成 2-4 次训练，每次 10-15 分钟，训练后查看反馈并由教师集中讲评 `[VERIFY]`。
- 主要评价：护患沟通与健康评估教师评分。
- 次要评价：学生自评临床能力、AI 准备度、模拟有效性、学习满意度。
- 过程指标：对话轮次、关键线索覆盖率、错误建议次数、反馈可采纳性。
- 质性资料：开放问题或小组访谈，主题分析。
- 统计：前后测配对检验；有对照组时比较组间变化；分类资料用卡方或 Fisher；质性资料编码归纳。

其中本地事实未知的地方继续标 `[VERIFY]`，不能编造。

### 5. 创新点要少而硬，不能写成“意义总结”

当前创新点有三条，但仍然偏概念：护理教学目标前置、可追溯流程、系统质量和教学效果同时评价。这些可以保留，但要更像“本项目区别在哪里”。

建议压成 3 条：

1. 护理能力导向的虚拟病人案例蓝图：把护患沟通、健康评估、情绪回应、健康教育转化为可执行的信息披露和评分规则。
2. 教师监管下的 LLM 虚拟标准化病人流程：模型不直接自由生成病例，而在案例事实、知识边界和专家审核下运行。
3. 结合表现评分与过程日志的教学评价：不只评价满意度，同时评价学生完成任务的行为证据和系统输出质量。

避免“国内领先”“填补空白”等未经证实表述。

### 6. 可行性需要从“文献可行”转向“本地可行”

V4 现在的可行性主要来自文献：已有研究支持、方案适中、风险可控。但标书评审更关心本项目能不能做完。

应补四类本地条件：

- 课程条件：依托哪门课/实训环节，是否有固定教学时段。
- 对象条件：学生来源、人数、教师组织方式。
- 专家条件：护理教育专家、临床护理专家、信息技术支持人员。
- 技术条件：模型调用方式、数据安全存储、是否有网页端/低代码/半自动流程。

如果本地条件还没确认，应把可行性写得保守，不要虚构团队和平台。

### 7. 预期成果要可验收，不能只写大类

当前成果写“案例库、系统原型、教学方案、评价工具包、研究报告”，方向对，但验收颗粒度不够。

建议写成可数成果：

- 护理虚拟标准化病人案例蓝图模板 1 套。
- 首批护理虚拟标准化病人案例 4 个。
- 虚拟患者交互与反馈原型 1 套。
- 教师评分表、学生训练说明、专家审核表各 1 套。
- 教学应用评价报告 1 份。
- 论文或教改成果 `[VERIFY]`。

## 建议的重写原则

后续重写时要按“该简单的简单，该详细的详细”处理：

- 简单写：研究目标、创新点、预期成果。它们应短、硬、可记住。
- 中等写：立项依据、研究现状、关键问题。它们应说明必要性和缺口，不提前写完整方案。
- 详细写：研究方法、技术路线、评价指标、质量控制。它们应具体到对象、流程、指标、时间点和分析方法。

## 建议的下一版结构

1. 前期研究基础：压缩为“问题基础、文献依据、已有准备、待补本地条件”。
2. 研究目标：3 条。
3. 研究内容：4 个任务包。
4. 拟解决的关键问题：3 个，分别对应教学目标转化、模型输出控制、评价证据不足。
5. 研究方法与技术路线：详细展开对象、案例构建、系统原型、干预流程、评价指标、数据分析、伦理质量控制。
6. 研究进度：按月份写任务和阶段成果。
7. 预期成果：按可验收清单写。

## 最需要用户补实的信息

1. 依托课程或实训环节名称。
2. 学生年级、班级、预计人数。
3. 是否有平行班可做对照。
4. 每名学生预计能完成几次虚拟病人训练。
5. 学校允许的模型调用方式。
6. 团队成员分工，尤其是护理专家、课程教师和技术支持。
7. 申报书要求的成果形式和数量。
