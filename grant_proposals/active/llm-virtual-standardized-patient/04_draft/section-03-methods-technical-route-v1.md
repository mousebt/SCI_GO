# 三、研究方法、技术路线

## （一）总体研究设计

本课题拟采用“需求分析—案例库构建—系统原型开发—专家审核—教学试点—混合评价”的研究设计。研究不是单纯验证某个大语言模型能否回答问题，而是围绕护理教学目标构建可控、可审查、可嵌入课程的虚拟标准化病人训练工具。

整体研究分为三个阶段：

1. 第一阶段为需求分析与方案设计。通过文献依据、课程目标梳理和师生访谈，明确护理虚拟标准化病人的应用场景、功能边界和评价指标。
2. 第二阶段为案例库与系统原型构建。基于护理场景蓝图，利用大语言模型辅助生成虚拟标准化病人案例，经护理专家审核后形成案例库，并构建交互原型。
3. 第三阶段为教学试点与效果评价。将系统用于护患沟通或健康评估训练，通过量化评价、教师/专家评分、对话日志分析和质性访谈综合评价其教学价值和风险边界。

## （二）研究对象与应用场景

### 1. 研究对象

研究对象初步包括三类：

1. 学习者：拟纳入 `[VERIFY] 护理本科生/实习前护生/护理实习生`，用于需求分析、系统试用和教学效果评价。
2. 教学与临床专家：拟邀请 `[VERIFY] 护理教育专家、健康评估课程教师、临床带教老师、专科护士` 参与场景选择、案例审核、评分标准制定和系统评价。
3. 技术支持人员：拟邀请 `[VERIFY] 信息技术人员/医学信息学人员/教育技术人员` 协助系统原型搭建、数据安全和运行维护。

### 2. 应用场景

根据现有文献和护理教学需求，本课题优先选择护患沟通与健康评估训练作为应用场景。具体可从以下场景中选择 3-5 个作为首批案例：

1. 入院护理评估；
2. 慢性病患者健康宣教；
3. 急性症状识别与初步评估；
4. 患者焦虑、抵触或不配合情境下的沟通；
5. 术前或术后护理宣教；
6. 老年患者、慢病患者或文化背景差异患者的沟通；
7. OSCE 护理站点训练。

最终场景应根据 `[VERIFY] 课程安排、教学大纲、已有案例资料和教师需求` 确定。

## （三）需求分析方法

### 1. 资料收集

采用半结构式访谈、焦点小组或问卷调查收集护理学生、护理教师和临床带教老师对虚拟标准化病人的需求。访谈内容包括：

1. 现有护患沟通和健康评估训练中的主要困难；
2. 学生最需要练习的护理场景；
3. 教师希望系统支持的教学目标和评价方式；
4. 虚拟病人应具备的角色特征、反馈方式和难度层级；
5. 对大语言模型应用的信任、担忧和伦理边界。

### 2. 资料分析

访谈资料采用主题分析法进行整理，提炼护理场景、功能需求、反馈需求和风险边界。问卷资料可采用描述性统计分析，形成场景优先级和功能需求排序。

### 3. 产出

本阶段形成《护理虚拟标准化病人需求分析报告》，作为案例库构建和系统功能设计的依据。

## （四）护理虚拟标准化病人案例库构建方法

### 1. 案例蓝图设计

每个虚拟标准化病人案例采用统一蓝图设计，拟包括以下内容：

1. 基本信息：年龄、性别、职业、家庭背景、文化背景等；
2. 临床情境：疾病或健康问题、就诊/入院原因、当前主要症状；
3. 护理任务：学生需要完成的沟通、评估、宣教或判断任务；
4. 护理评估要点：必须询问或识别的关键信息；
5. 情绪与沟通设定：焦虑、担心、回避、抵触、配合不足等；
6. 标准化应答：学生问到关键问题时的回答范围和信息披露节奏；
7. 安全边界：系统不应主动提供的诊疗建议、未经验证信息或敏感内容；
8. 评分要点：沟通表现、信息采集、评估完整性、健康宣教和护理判断；
9. 反馈规则：训练结束后向学生反馈的内容和改进建议。

### 2. 大语言模型辅助生成

在明确蓝图后，使用大语言模型生成病例初稿、角色画像、对话应答规则和反馈文本。生成过程中采用结构化提示词，要求模型严格依据蓝图输出，不自行扩展未经审核的医学或护理内容。

生成内容包括：

1. 虚拟病人的基本设定；
2. 病情和护理问题背景；
3. 学生可能提问及标准化回答；
4. 情绪变化和沟通反应；
5. 训练后反馈模板；
6. 教师评分参考。

### 3. 专家审核与迭代修订

每个案例均需经过护理专家审核。审核维度包括：

1. 护理知识准确性；
2. 临床情境真实性；
3. 教学目标匹配度；
4. 沟通难度适宜性；
5. 角色表现一致性；
6. 反馈建议可操作性；
7. 伦理和隐私风险。

专家审核后，将案例分为“可用”“修改后可用”“暂不纳入”三类。修改后案例再次审核，形成最终案例库。该流程用于避免大语言模型无审核批量生成导致的病例重复、信息错误和教学目标偏移。

## （五）虚拟标准化病人交互系统构建方法

### 1. 系统设计原则

系统设计遵循四项原则：

1. 护理场景前置：系统围绕护理课程目标和护理任务设计，而不是通用医学问答。
2. 内容可追溯：虚拟病人的知识来源于经审核的案例库和知识边界。
3. 教师可监管：教师能够查看案例、训练记录和系统反馈。
4. 风险可控制：系统设置安全边界、错误纠正和隐私保护机制。

### 2. 系统模块

系统原型拟包括以下模块：

1. 病例知识库模块：保存经专家审核的病例资料、护理评估要点、标准化回答和反馈规则。
2. 角色画像模块：控制虚拟病人的身份、情绪、沟通方式、信息披露节奏和配合程度。
3. 对话记忆模块：记录学习者已询问问题和已获得信息，维持多轮对话一致性。
4. 问题识别模块：识别学习者问题是否涉及病史、症状、评估、宣教、情绪回应或不适当提问。
5. 安全边界模块：限制系统输出未经审核的诊疗建议、药物建议、隐私信息或错误护理判断。
6. 反馈生成模块：根据训练日志生成结构化反馈，包括优点、遗漏、风险提示和改进建议。
7. 教师端记录模块：保存训练过程和评价结果，便于教师复盘和研究分析。

### 3. 技术实现方式

根据课题经费、平台条件和数据安全要求，系统可采用以下实现方式之一：

1. 轻量级原型：基于受控提示词、案例知识库和人工审核流程构建可试用系统，适合院级或教改课题。
2. 检索增强原型：基于经审核案例库进行检索增强生成，使虚拟病人回答尽量限制在授权知识范围内。
3. 多模块/多智能体原型：将角色扮演、记忆管理、反馈生成和安全审查拆分为不同模块，提高角色一致性和反馈质量。

本课题初期建议采用“轻量级原型 + 案例知识库 + 专家审核 + 对话日志分析”的稳妥路线；若技术条件允许，可进一步引入检索增强或多智能体模块。

## （六）教学试点与效果评价方法

### 1. 试点设计

根据实际教学安排，拟采用以下设计之一：

1. 单组前后测设计：同一批学生在使用系统前后完成能力自评、任务表现评价和使用体验评价。
2. 准实验设计：设置虚拟标准化病人训练组和常规教学组，比较两组训练后表现。
3. 交叉设计：学生先后体验不同训练方式，如虚拟标准化病人与传统情景讨论或 VR/视频案例训练，比较不同方式的学习体验和能力变化。

若课题为院级或教学改革课题，建议优先采用单组前后测或小规模准实验设计，以保证实施可行性。

### 2. 评价指标

评价指标分为系统层面、学习者层面、教学层面和风险层面。

系统层面：

1. 护理知识准确性；
2. 事实一致性；
3. 角色一致性；
4. 误导性回答发生情况；
5. 交互稳定性；
6. 反馈可操作性。

学习者层面：

1. 自评临床能力；
2. 护患沟通能力；
3. 健康评估能力；
4. AI 准备度；
5. 学习满意度；
6. 系统可用性和使用意愿。

教学层面：

1. OSCE 或情境任务评分；
2. 教师/专家评分；
3. 关键评估点覆盖率；
4. 学生反思质量；
5. 教师工作负担和课程整合可行性。

风险层面：

1. 隐私保护；
2. 知识错误；
3. 过度依赖；
4. 伦理接受度；
5. 教师监管需求。

### 3. 数据收集

拟收集以下资料：

1. 学生基本资料和学习背景；
2. 训练前后量表数据；
3. 教师或专家评分表；
4. 虚拟病人对话日志；
5. 系统反馈记录；
6. 学生访谈或开放性反馈；
7. 教师使用反馈。

所有数据应去标识化保存。对话日志仅用于教学评价和研究分析，不纳入与课题无关的系统训练或公开数据集。

### 4. 数据分析

量化资料根据样本量和研究设计采用描述性统计、配对检验、组间比较或非参数检验。若样本量较小，重点报告变化趋势、效果量和可行性指标，不夸大因果结论。

质性资料采用主题分析法，围绕系统真实性、反馈价值、信任、学习负担、伦理顾虑和课程整合条件提炼主题。

对话日志采用内容分析或评分表分析，关注关键评估点覆盖率、沟通策略、遗漏信息、系统错误反馈和学生改进空间。

## （七）质量控制与风险控制

### 1. 内容质量控制

所有虚拟标准化病人案例均需经过专家审核后使用。大语言模型生成内容不得直接进入教学试点。案例修订过程保留版本记录，确保每个训练场景的来源、修改和审核过程可追溯。

### 2. 系统输出控制

系统回答应限制在经审核的病例知识库和角色设定范围内。对于超出训练目标的问题，系统应使用安全提示或引导学生回到护理评估任务，避免输出未经验证的诊疗建议。

### 3. 教学过程控制

虚拟标准化病人作为形成性训练工具使用，不替代教师指导、真人标准化病人或真实临床接触。教师需参与训练目标设定、反馈解释和错误纠正。

### 4. 伦理与隐私控制

若使用真实病例或学生训练记录，应进行脱敏处理并获得伦理审批或教学研究备案。学生使用系统前应知情同意，明确数据用途、保存方式和退出权利。

### 5. 研究结论控制

若采用小样本试点，本课题结论应定位于可行性、可用性和初步应用效果，不直接推断其能够替代传统教学或显著提高真实临床能力。

## （八）技术路线

本课题技术路线可概括为：

`文献与课程目标梳理 -> 师生需求分析 -> 护理教学场景筛选 -> 虚拟标准化病人案例蓝图设计 -> 大语言模型辅助生成病例初稿 -> 护理专家审核与迭代修订 -> 构建病例知识库与角色画像 -> 开发交互与反馈原型 -> 专家评价和可用性测试 -> 教学试点应用 -> 量化与质性混合评价 -> 系统和案例库优化 -> 形成成果`

其中，三个关键闭环贯穿研究全过程：

1. 案例质量闭环：案例蓝图 -> LLM 生成 -> 专家审核 -> 修订 -> 定稿。
2. 系统安全闭环：知识库约束 -> 安全边界 -> 日志监测 -> 错误纠正。
3. 教学评价闭环：训练应用 -> 学生表现 -> 教师反馈 -> 系统优化。

通过上述路线，本课题将大语言模型的生成能力转化为可控的护理教学工具，形成兼顾技术可行性、教学适配性和伦理安全性的虚拟标准化病人构建方案。
