# 架构说明

## 五层结构

1. **规则层 `config/`**：所有论文共享的底层逻辑，是可审计的单一来源。
2. **模板层 `templates/`**：保证每个新项目从同一套结构和检查点开始。
3. **方向层 `research_directions/`**：论文前的研究方向探讨、可行性判断和候选课题孵化；只有成熟方向才转入论文项目。
4. **项目层 `papers/`**：事实、证据、正文、评审和投稿文件严格按论文隔离。
5. **学习层 `knowledge/`**：只保存具有来源、适用范围和验证记录的可复用技巧。

## 为什么不把规则复制到每篇论文

复制会产生漂移：旧论文修过的规则，新论文可能仍使用旧版本。因此论文默认引用根目录规则，只在 `paper.yaml` 中记录必要覆盖。模板记录创建时的逻辑版本，便于追溯。

## 每篇论文的目录语义

| 目录 | 内容 |
|---|---|
| `00_admin` | 人员、状态和里程碑 |
| `01_planning` | 研究简报、一句话论证、目标期刊 |
| `02_evidence` | 主张—证据表、术语表、数据来源 |
| `03_manuscript` | 唯一正文源文件与章节 |
| `04_figures` | 可编辑源图和获批成图 |
| `05_references` | 文献库与检索记录 |
| `06_review` | 变更、内部意见、审稿回复 |
| `07_submission` | 投稿清单和正式提交包 |
| `90_learning` | 本项目经验及验证记录 |
| `tmp` | 可删除的中间文件和一次性脚本 |
