# 标准写作流程

## 选择启动模式

- `existing_zh_manuscript`：先审计中文稿结构并锁定事实锚点，再按 SCI 章节职能重构英文稿；不是逐句翻译。
- `materials_from_scratch`：先建立主张—证据表和论证链，再从 Results 开始撰写。
- `auto`：根据材料完整度判断；不确定时由用户确认。

详细规则见 `config/start-modes.md`。

## 启动

运行 `scripts/new-paper.ps1` 后，完成研究简报。必须先明确核心主张、关键证据、边界、目标读者和目标期刊；信息缺失时只建立带占位符的提纲。

## 证据建模

在写完整正文前维护两张表：

- `claim-evidence.csv`：每项主张对应何种证据、位于哪里、当前是否充分。
- `terminology.csv`：规范术语、首次定义和来源中的变体。

## 起草与修订

按 `config/writing-logic.md` 的顺序推进。每次反馈优先局部修订；只有核心论证改变时才重建结构。重大决定写入变更日志，常规文字微调可合并记录。

## 质控门

提交前至少通过：

- 主张均有证据或被明确降级。
- 数字、样本量、统计量和图表互相一致。
- 引用已核验，无虚构条目。
- 术语、缩写、单位和图号一致。
- 结论没有越过研究边界。
- 投稿要求、数据可用性、作者贡献和利益冲突材料齐备。

## 项目学习

将有效或失败的技巧记录在 `90_learning/lessons.csv`。只有重复可用、范围明确、有证据且被批准的条目才会同步到共享知识。项目特有技巧保留在本项目，不强行推广。
