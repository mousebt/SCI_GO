## 1. 论文定位

### 1.1 研究类型

回顾性描述性基线研究与LLM辅助结构化报告原型的形成性技术评价。

论文不是44例数据质量改进或前后对照研究，不是报告字段共识研究，不是FAERS研究、新模型研究、真实语音研究或临床实施研究。

### 1.2 建议题目

中文：**从症状标签到结构化草稿：造影剂不良事件LLM辅助报告原型的开发与语义安全形成性评价**

英文：**From Symptom Labels to Structured Drafts: Development and Formative Semantic-Safety Evaluation of an LLM-Assisted Contrast Adverse Event Reporting Prototype**

如果最终没有独立锁定评价，题目降级为“开发与错误分析”，不得使用“评价”或“验证”。

### 1.3 一句话论证

> 本院固定44例手工登记主要保存患者基本信息和极短症状标签，不能由当前数据集还原造影剂暴露、时间、处置和结局；基于这一信息边界，本研究实现了来源约束、带语义护栏和强制人工审核的LLM结构化报告草稿原型，并通过分层合成叙述评价其工程可执行性及复杂语义风险。

正式稿若加入独立评价，可在末尾补充“及护栏在未参与开发语料中的表现”；在此之前不得写成已验证的泛化结论。

### 1.4 论证链

`固定44例显示症状标签与完整事件叙述之间的结构差距 → 以正式报告要求定义目标输出Schema → LLM将完整叙述整理为结构化草稿 → 100条开发语料揭示逐字来源检查的语义盲区 → 确定性护栏修复已知模式 → 独立锁定文本评价残余风险`

## 2. 核心研究问题

1. 固定44例手工登记在人口学、症状类别、文本长度和字段结构上呈现什么特征？
2. 来源约束、带语义状态控制和人工审核的LLM原型能否稳定生成结构化报告草稿？
3. 逐字来源检查为什么不能区分患者事实与否定、冲突、不确定、模板、假设或补写指令？
4. 增加确定性语义护栏后，已知泄漏模式在开发集回归和独立锁定文本中的表现如何？

## 3. 研究设计

### Phase A：固定44例回顾性描述

分析单位为1例人工登记案例，共44例。固定字段为编号、性别、年龄和事件简短描述。分析性别、年龄、事件文本长度、非互斥多标签症状类别，以及数据集是否设置造影剂、给药、时间、处置、结局和关系字段。仅做描述性统计，不做显著性检验。

字段不存在仅指当前提供的登记数据集，不代表完整护理病历没有相应信息。不得补录字段、追溯病历、修改原始案例、模拟缺失信息或将44例转换为完整结构化报告。

### Phase B：目标Schema与原型

目标Schema来源于正式个例安全报告要求、MedDRA术语原则及适用造影剂临床指南；44例只说明为何需要从症状标签转向更完整的事件叙述，不作为标准字段的充分依据。

原型流程：

`完整叙述文本 → LLM按固定Schema整理 → 非空事实逐字来源检查 → 否定/冲突/不确定/模板/假设/指令护栏 → 缺失字段提示 → 人工审核 → 禁止自动提交`

输出是报告草稿，不是诊断、因果判断、严重性判断、治疗建议或法定报告决定。

### Phase C：100条开发语料形成性评价

语料为100条中文合成护士叙述；常规80条、压力20条；L1–L5为15/30/35/10/10。模型为Gemini 2.5 Flash，temperature 0，thinking budget 0，单并发。

开发过程为：全量运行和压力层审计 → 根据语义错误修改确定性护栏 → 在相同固定压力集上回归。

这一阶段报告请求成功、运行错误、来源覆盖、人工审核状态、自动提交违规、候选语义错误类型、安全标记和开发集回归，不提供独立准确率或临床安全性。

### Phase D：独立锁定文本评价

这是正式稿使用“形成性评价”定位的最低新增实验，不涉及新增真实病例或修改44例。

要求：在代码、Prompt、Schema和护栏冻结后锁定未参与开发的文本；预先给出字段、关系和语义状态参考答案；对同一独立文本保存原始LLM结果和完整护栏结果；报告字段级、关系级、遗漏、无来源事实和语义泄漏；单列否定、冲突、不确定、模板、假设和指令性文本；对高风险错误进行临床核对。

不预设不存在的数据、样本量、阈值、评价者人数或显著性结果。

## 4. Results结构

### 4.1 固定44例登记的特征

报告男性24例、女性20例；年龄统计；非互斥症状类别；事件描述中位数2个字符及其分布。段落结论限定为：当前登记主要保存患者基本信息和症状标签。

### 4.2 固定登记数据集的信息边界

报告当前数据集包含性别、年龄和事件描述，未设置具体造影剂、剂量/途径、给药时间、事件时间、处置、结局和关键关系字段。

不得直接写“护士漏填”或“记录不完整”；准确表述是“这些字段未进入当前提供的数据集结构”。

### 4.3 结构化草稿原型

报告固定Schema、来源定位、语义状态、缺失提示、人工审核和禁止自动提交。技术参数保持可复现，但不展开成模型设计论文。

### 4.4 100条开发语料的工程运行

报告100/100完成、941项护栏后非空事实有逐字来源、全部保持待人工审核、自动提交违规0及运行时间。明确这些指标是工程可执行性，不是内容准确性。

### 4.5 逐字来源检查的语义盲区

报告初始压力层19/20存在候选语义问题及错误类别。核心发现是：字符串存在于输入中不等于它属于患者的肯定事实。19/20来自工程审计，不写成临床错误率。

### 4.6 语义护栏修订与开发集回归

报告护栏类型、固定20条回归、97项非空事实、14个安全标记、0自动提交违规和22项离线测试。准确表述是“修复前已识别的同类泄漏在固定开发集回归中未再发现”。

不得写“错误率由95%降至0%”或“安全性提高到100%”。

### 4.7 独立锁定文本结果

待新实验后填写。没有该结果时，正文停止在开发与错误分析，不制造占位性能数字。

## 5. Discussion结构

### 5.1 主要发现

固定登记数据说明症状标签不足以重建完整事件过程；开发实验说明LLM能够执行结构化整理，但词汇来源忠实并不保证语义状态正确。

### 5.2 44例的作用与边界

44例是临床问题的本地证据，不是LLM训练集、验证集或干预前对照。数据结构固定使研究能够界定现有登记信息边界，但不能评价完整病历或护士个人记录质量。

### 5.3 为什么结构化草稿仍需要人工审核

否定、冲突、自我纠正、不确定和模板内容都可能包含逐字来源，但不应直接写入患者事实。因此来源校验、语义状态控制和人工审核分别解决不同风险。

### 5.4 对护理记录的意义

意义限定为：原型提供一种把更完整自由叙述整理为待核对草稿的技术路径。由于没有护士实际使用、计时或工作负担数据，不讨论效率改善或临床采纳。

### 5.5 局限性

单中心固定44例、字段极少、症状分类仍需作者确认；合成语料；开发集参与调参；初始错误为工程审计；单一云端模型；无真实音频；无真实工作流或患者结局评价。

### 5.6 后续研究

只提出与当前证据直接相邻的工作：独立文本评价和真实场景外部验证。护士可用性、语音识别或多中心实施作为未来扩展，不列为当前论文缺失结果。

## 6. Conclusion契约

当前允许的结论：

> 固定44例手工登记主要保存基本信息和极短症状标签。来源约束的LLM原型能够在合成开发文本上生成结构化、待人工审核的报告草稿，但压力测试显示逐字来源检查不能区分患者事实与复杂语义范围。确定性护栏已针对已知模式完成开发集回归；独立评价仍决定其可推广边界。

如果独立评价完成，再根据真实结果增加一句，不预先承诺方向。
