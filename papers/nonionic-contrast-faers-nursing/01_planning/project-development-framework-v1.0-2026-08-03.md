# 项目开发框架 v1.0：44例登记缺口驱动的结构化报告原型与语义安全评价

日期：2026-08-03  
状态：已被`integrated-manuscript-framework-voice-llm-v1.0-2026-08-03.md`取代；保留为历史讨论  
适用范围：本院44例登记分析、报告字段、LLM/RAG原型、测试语料、评价和论文映射  
范围决策：FAERS退出当前项目论证链和原型知识层；既有FAERS分析只保留为范围外资产，不删除。

## 1. 项目为什么存在

本院已有44例造影剂使用后人工登记案例。当前可用数据字段为编号、性别、年龄和极简事件描述。它们能够说明“出现了什么表现”，但当前登记数据集没有保存具体造影剂、给药、时间、处置、结局以及这些要素之间的关系。

本项目解决的不是病例发现、发生率估计或自动临床决策，而是一个明确的信息转换问题：

> 如何把护士提供的自由叙述整理为字段、关系、缺失和不确定状态明确，来源可追溯且必须人工审核的造影剂不良事件报告草稿。

## 2. 固定事实与证据边界

### 2.1 已确认事实

- 本院登记案例数为44例；重复编号是录入错误，不删除病例。
- 近5年约9,500人次只作为业务背景，不用于计算发生率或漏报率。
- 44例现有字段为编号、性别、年龄和事件简短描述。
- 已有分析显示男性24例、女性20例，平均年龄54.0±13.5岁；这些统计须与最终分析表保持一致。
- 当前多标签症状分类为胃肠道21例、皮肤或过敏样表现10例、局部外渗或肿胀7例、呼吸道或鼻部表现6例、神经系统表现1例；正式使用前仍需临床复核。
- 事件描述中位数为2个字符，四分位数2–4.25，范围2–12。
- 已实现可运行原型、固定JSON Schema、来源检查、语义护栏、人工审核状态和禁止自动提交规则。
- 已完成100条80/20合成开发语料的Gemini运行，以及固定20条压力开发集的错误发现和回归。

### 2.2 当前证据只能支持

- 44例登记数据集的信息结构主要停留在基本信息和简短症状层面。
- 原型能够在合成开发语料上执行结构化整理、来源定位和人工审核状态控制。
- 逐字来源存在不能证明某个文本片段是患者的肯定事实。
- 已知的否定、冲突、不确定、模板、假设和补写指令泄漏模式已在固定开发集上进行针对性修复。

### 2.3 当前证据不能支持

- 44/9,500是发生率或漏报率；
- 当前登记数据集缺字段等同于完整护理病历缺字段；
- 原型提高了真实报告质量、效率、完整性、可用性或护士满意度；
- 固定开发集回归证明系统具有临床安全性或泛化能力；
- 浏览器语音入口已经构成可复现的语音识别研究；
- LLM可以判断因果、严重性、可报告性、治疗或自动提交。

## 3. 单一开发链

`44例登记数据结构审计 → 候选报告字段与关系 → 来源约束的结构化草稿原型 → 100例开发语料暴露语义错误 → 确定性护栏修订 → 独立文本评价 → 有边界的形成性结论`

这是当前项目唯一主链。以下内容不再加入：FAERS信号、医院流程再造、上报率干预、护士工作负担研究、真实语音识别评价。后四项只有在作者另行启动新阶段时才评估。

## 4. 开发对象

### 4.1 44例登记分析层

作用：量化当前数据集记录了什么、没有设置什么字段，以及事件描述的简短程度。

正式输出：去标识化44例分析表和数据字典；性别、年龄、文本长度和多标签症状类别；当前数据集字段存在性表；“数据集字段缺失不外推至完整病历”的边界声明。

最低补充：准确五年起止日期、登记来源说明、临床人员对多标签分类的复核、伦理豁免的机构口径。

### 4.2 候选报告结构层

作用：定义原型需要整理的内容，不声称制定行业标准。

核心模块：患者与报告者；造影剂及给药；事件原始表述与候选规范术语；给药和事件时间；生命体征与升级处置；管理措施与转归；产品—事件—时间—处置—转归关系；已提供、缺失、不适用、否定、冲突和不确定状态；原文来源；人工审核状态。

字段来源只保留正式报告要求、MedDRA原则、适用造影剂临床指南以及44例登记数据结构缺口。FAERS不再作为字段、提示、RAG或测试场景的来源。

字段在临床内容核对前称“候选字段”，核对后可称“经临床复核的字段集”；除非执行相应方法，不称专家共识、Delphi或验证标准。

### 4.3 原型层

当前目标流程：

`人工输入或人工校正文本 → 候选字段检索 → LLM按Schema整理 → 逐字来源检查 → 语义范围护栏 → 缺失/冲突提示 → 人工审核 → JSON草稿`

必须保留：输入原文；模型、Prompt、Schema、知识库、代码和运行版本；每个非空字段的来源片段；安全标记；`pending_human_review`；`automated_submission_permitted=false`。

必须删除或重建：`knowledge.json`中的FAERS事件和时间条目；Prompt、说明文档和测试中把FAERS作为患者事实提示来源的内容；任何依赖FAERS锚定候选事件的评价逻辑。

语音入口保留为界面能力，但本阶段不评价ASR，也不在题目和结论中称语音系统。

### 4.4 评价层

#### 已完成：开发评价

- 100条合成文本，常规80条、压力20条；L1–L5为15/30/35/10/10。
- Gemini 2.5 Flash单并发100/100成功。
- 941项护栏后非空事实均有逐字来源。
- 全部保持待人工审核，自动提交违规0。
- 初始压力层19/20存在候选语义问题。
- 修订后固定20条开发集未再发现同类已知泄漏。
- 22项离线测试通过。

以上只作为开发过程和错误机制证据。

#### 下一阶段：独立文本评价

目标不是继续增加类似文本，而是检验修订后的系统能否处理未参与开发的案例。

最低设计：独立文本在系统、Prompt和护栏冻结后锁定；为每条文本建立字段、关系和语义状态参考答案；临床评价者核对参考答案和高风险错误；报告字段级和关系级结果、遗漏、无来源事实及语义泄漏；单独列出否定、冲突、不确定、模板、假设和指令性文本；保存逐例输出与裁决依据。

不预先虚构样本量、通过阈值、评价者人数或统计显著性。具体方案根据可获得评价资源锁定，并在正式运行前记录。
