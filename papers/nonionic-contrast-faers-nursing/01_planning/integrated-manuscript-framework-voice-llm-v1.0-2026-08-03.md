# 整篇论文框架 v1.0：手机语音—LLM辅助ADE报告生成

日期：2026-08-03  
状态：当前唯一有效的论文总体框架  
作者锁定事实：44条本院ADE登记记录；现有ADE收集数量有限、信息质量不足；研究目标是通过LLM分析护士手机录音生成高质量ADE报告；100条合成护士口述记录用于可行性测试；FAERS不进入论文。

## 1. 论文的核心问题

本院近5年约9,500人次造影检查中，现有人工登记材料只有44条ADE记录。该数量提示现行收集渠道获得的案例有限，但在缺少主动病例发现和完整分母定义时，不能直接计算漏报率或真实发生率。

质量问题可以由现有数据直接观察：44条记录的固定字段仅包括编号、性别、年龄和极简症状描述，缺少形成可复核ADE报告通常需要的具体产品、给药、时间、处置、转归及其关系。该结论只针对现有登记数据集，不外推为完整护理病历或护士实际观察中没有这些信息。

论文要解决的问题是：护士可能掌握更完整的事件经过，但传统极简登记没有有效承载这些信息。手机录音允许护士以自然语言快速描述事件，ASR和LLM可以把叙述转化为结构化ADE报告草稿，但必须控制遗漏、幻觉、否定、冲突和不确定信息误写等风险。

## 2. 一句话论证

> 针对本院造影剂ADE登记数量有限且现有44条记录主要停留在极简症状描述的问题，本研究开发了“护士手机录音—语音转写—LLM结构化整理—来源与语义安全校验—人工审核”的ADE报告生成流程，并以100条分层合成护士口述记录评价其从自由叙述生成高质量、可追溯报告草稿的技术可行性与安全边界。

其中“高质量”必须拆解为可测量维度：字段完整性、关系明确性、来源忠实性、语义状态正确性、关键事实准确性、无来源事实、遗漏和人工审核状态。不能把“高质量”作为未经测量的形容词。

## 3. 单一论证链

`44条真实登记揭示ADE收集数量与信息承载问题 → 设计手机语音采集和结构化ADE报告流程 → 100条合成护士口述覆盖常规与复杂情境 → LLM完成结构化提取 → 来源检查暴露语义盲区 → 语义护栏修订 → 评价系统可行性、报告质量和残余风险`

各材料职责：

- 44条真实登记：证明临床问题存在并描述问题形态；
- 手机录音流程：提出解决路径；
- 100条合成护士口述：作为系统测试数据，不替代真实临床病例；
- Gemini运行和护栏回归：提供技术可行性与错误机制证据；
- 人工审核：是系统设计的一部分，不是失败后的补救。

## 4. 当前环境的证据状态

### 4.1 已完成

- 44条固定登记的描述性分析；
- 报告字段、关系、JSON Schema、RAG、来源检查和人工审核状态；
- 浏览器手机/网页录音与语音转写入口；
- 100条合成护士口述脚本，80条常规、20条压力，L1–L5为15/30/35/10/10；
- Gemini 2.5 Flash对100条口述转写文本的全量处理；
- 100/100请求成功，941项护栏后非空事实有逐字来源，全部保持待人工审核，自动提交违规0；
- 压力层初始工程审计发现19/20存在候选语义问题；
- 针对否定、冲突、不确定、模板、假设和补写指令增加护栏；
- 固定20条开发集回归和22项离线测试。

### 4.2 尚未完成

当前100条材料在仓库中是JSON/CSV形式的合成口述文本，没有对应音频文件。因此现有结果支持“LLM分析口述转写文本”的可行性，不支持“手机录音端到端生成报告”的完整结论。

若论文题目和主要结论保留手机语音，需要补充：

- 由100条口述脚本形成的合成或模拟录音；
- 固定、可记录版本的ASR；
- 人工逐字稿；
- ASR字符/词错误及药名、剂量、时间等关键错误；
- 人工逐字稿输入与ASR输入的下游结构化报告差异。

## 5. 研究设计

### Phase 1：本院固定44条登记的回顾性描述

目的：证明现有ADE收集在数量和信息结构上存在现实问题。

数据：固定44条记录；不新增、不补录、不修改字段。  
分析：性别、年龄、症状类别、文本长度、字段存在性。  
数量表述：近5年约9,500人次背景下仅获得44条登记，称“登记数量有限”或“现有收集产出有限”；不称已证明漏报。  
质量表述：现有数据集仅承载基本信息和极简症状，不能形成产品—给药—事件—时间—处置—转归链；不称护士没有观察或记录这些信息。

### Phase 2：手机语音—LLM ADE报告流程开发

输入：护士手机录音。  
处理链：

`手机录音 → ASR转写 → 人工可校正文本 → RAG/字段提示 → LLM按JSON Schema整理 → 逐字来源校验 → 语义状态护栏 → 缺失/冲突提示 → 护士审核 → ADE报告草稿`

目标输出模块：患者与报告者、疑似产品及给药、事件、时间、生命体征、处置、升级、转归、随访、字段关系、缺失/不确定状态、来源片段和审核状态。

系统禁止：自动判断因果关系、严重性、法定可报告性和治疗；禁止自动提交；知识库内容不得填充患者事实。

### Phase 3：100条合成护士口述测试数据

构建目的：在不暴露真实患者信息的条件下覆盖护士自然口述中的常规信息和复杂语义。

构成：

- 常规层80条：完整或部分缺失的临床叙述；
- 压力层20条：否定、冲突、不确定、自我纠正、模板、假设、拟写和补全指令；
- L1–L5：15、30、35、10、10条。

语料不是44条登记的扩写版，不与44条逐例对应，也不用于推断真实事件分布。

### Phase 4：分层系统评价

#### 4.1 语音转写层

仅在音频形成后评价：

- 字符错误率或适合中文的转写错误指标；
- 造影剂名称、剂量、时间、症状和处置等关键词错误；
- 噪声、语速、停顿和自我纠正条件；
- ASR错误向ADE字段和关系错误的传播。

#### 4.2 LLM结构化报告层

评价：

- 字段完整性；
- 字段级precision、recall和F1；
- 产品—事件—时间—处置—转归关系正确性；
- 来源忠实性和无来源事实；
- 否定、冲突、不确定、模板、假设和指令泄漏；
- 遗漏和错误确定；
- 人工审核状态及自动提交违规。

#### 4.3 护栏贡献

现有修复前后结果属于开发集诊断。若要正式声称护栏改善性能，应在未参与开发的锁定测试或预先冻结输出上比较基础流程与完整护栏流程。

## 6. 全文结构

# 1 Introduction

## 1.1 ADE收集为何重要

护士最接近造影剂给药、症状观察和即时处置；其叙述可能包含形成高质量ADE报告所需的事实。

## 1.2 当前收集的数量和质量问题

以本院近5年约9,500人次和44条固定登记为临床起点：案例收集数量有限，记录主要为极简症状标签，产品、时间、处置和转归链没有进入当前数据集。

## 1.3 手机语音与LLM的机会和风险

手机录音降低自由叙述的输入门槛；ASR和LLM可以结构化整理，但逐字来源、语义正确和临床事实并不等价。

## 1.4 研究目的

开发手机语音—LLM ADE报告流程；用100条合成护士口述评价语音转写、结构化报告质量、复杂语义安全及人工审核边界。

# 2 Methods

## 2.1 Study design

采用分阶段开发与临床可行性评价设计，包括四个相互独立、职责不同的证据层：

1. 固定44条真实ADE登记记录的回顾性描述，用于界定现有收集数量和信息质量问题；
2. 100条基于临床情境构建的模拟护士口述开发集，用于提示词、Schema、来源校验和语义护栏的开发，不用于无偏性能估计；
3. 额外构建并冻结的独立模拟测试集，以及可扩展至1000条的自动化压力测试集，用于评价未见病例中的字段、关系和语义安全表现；
4. 20条连续或按预设规则纳入的去标识化真实临床录音试点，由临床专家建立参考报告并复核系统输出，用于评价真实工作流中的初步可行性和残余风险。

各层数据不得合并为一个总体准确率。20条真实临床录音属于先导性临床评价，不作为正式临床验证或可推广性证据。

## 2.2 Setting and fixed local registry

报告时间范围、约9,500人次背景、44条来源、固定字段和伦理口径。

## 2.3 Analysis of collection quantity and information quality

数量只描述登记产出，不推断漏报；质量使用文本长度、字段存在性和关系可构建性描述。

## 2.4 Definition of a high-quality ADE report

预先定义完整性、关系明确性、来源忠实性、语义正确性、缺失/不确定状态和人工审核。

## 2.5 Mobile voice-to-report system

描述手机录音、ASR、文本校正、RAG、Gemini、Schema、来源检查、语义护栏和人工审核。

## 2.6 Clinically grounded simulated nurse-dictation development set

100条开发数据按真实临床案例的叙事逻辑重新构建，但其证据属性仍为模拟病例，不得写成真实患者病例。每条应形成完整、可独立理解的护士口述场景，并保持患者、造影剂、给药、事件、时间、处置和转归之间的临床与时间一致性。

病例构建以本院44条记录中观察到的症状类型和表达特点、临床护理场景及正式ADE报告信息域为依据，不复制或补写某一真实患者。记录病例构建规则、80/20构成、L1–L5分层、常规与压力情境、字段覆盖、关系覆盖和语义陷阱。

该100条数据允许用于模型、提示词和护栏迭代，因此论文中明确称为“开发集”，其回归结果只说明已识别错误模式得到纠正，不作为独立泛化性能。模拟数据用于形成数据字典、标注手册、错误分类、严重程度分级、评分规则和裁决流程；它本身不能构成本地临床金标准。

论文规范称谓为“基于临床情境构建的模拟护士口述病例（clinically grounded simulated nurse-dictation cases）”，不使用“真实病例100例”。

## 2.7 Local evaluation standard and expert reference process

本节定义评价标准，而不是报告评价结果。评价标准在独立测试和真实临床试点开始前冻结，包括：

- ADE报告数据字典及字段、事件—产品、事件—时间、事件—处置和事件—转归关系定义；
- 完整性、关键事实准确性、来源忠实性、关系正确性和语义状态正确性的操作性定义；
- 否定、冲突、不确定、自我纠正、模板、假设、补写指令和无来源事实的错误分类；
- 一般错误与可能影响临床判断或后续报告的高风险错误分级；
- 缺失、无法判断和不适用的编码规则；
- 专家分歧的裁决规则及评分表。

参考标准由临床专家基于原始口述或人工逐字稿独立形成，而不是仅在看到LLM输出后判断其是否合理，以降低锚定偏倚。优先采用两名专家独立标注、第三名专家裁决分歧；如实际只能配置一名专家，必须在方法和局限中明确降级。模拟病例的预设答案只有经过专家审核和裁决后才能称为该病例的参考标准。

## 2.8 Locked simulated test set and large-scale stress testing

在100条开发集之外，另行构建不参与提示词或护栏迭代的锁定模拟测试集。建议首先形成100–200条经专家确认参考答案的未见病例，以获得可解释的字段、关系和语义评价；实际数量、抽样规则和专家工作量需在实施后据实填写 `[VERIFY]`。

模拟病例可进一步扩展至最多1000条，用于自动化压力测试和覆盖少见表达、信息缺失、长文本、时间冲突、否定、不确定及指令干扰。规模化压力测试的主要目的为发现错误边界，不以未经专家审核的1000条生成答案替代临床金标准。若不能保证病例多样性、去重、临床一致性和质量筛查，不以扩大数量代替高质量测试设计。

## 2.9 Evaluation procedures and outcome measures

本节说明各数据层如何运行和判定，Results只报告实际观察值。记录模型名称与版本、运行参数、输入输出格式、失败判定和重试策略。分别报告：

- 字段级存在性、准确性、遗漏和无来源增加；
- 关键关系正确性；
- 来源忠实性与语义状态正确性；
- 各类错误及高风险错误的病例级数量和比例；
- 人工审核后的可接受、需修改和不可接受结论；
- 开发集护栏修订前后回归结果；
- 锁定模拟测试集的独立性能。

开发集、锁定模拟测试集、自动化压力测试和真实临床试点分别报告，不汇总为单一准确率，也不把同一病例内多个字段当作相互独立的临床样本。

## 2.10 Real-clinical-audio pilot and end-to-end voice evaluation

在完成并冻结评价标准后，纳入20条去标识化真实临床护士录音 `[EVIDENCE NEEDED: 伦理批准、知情同意或豁免、连续/预设纳入规则及安全存储方案]`。该样本用于真实环境中的先导性可行性和定性错误审计，不用于声称正式临床验证、普遍准确性或推广效果。

每条录音形成经人工校对的逐字稿，并使用固定版本ASR生成自动转写。系统同时运行两条路径：

1. 人工校对逐字稿→LLM，用于隔离评价LLM结构化分析；
2. ASR自动转写→LLM，用于评价完整手机录音—报告流程。

两名专家在查看系统输出前，依据录音和人工逐字稿独立形成参考报告；随后在盲化或随机化呈现条件下复核系统输出，分歧由第三名专家裁决。评价ASR转写错误、关键药名/剂量/时间错误、字段和关系错误、语义状态错误、高风险错误、专家可接受性，以及ASR错误向下游ADE报告的传播。20例只能支持初步临床可行性；是否扩大真实病例样本，应依据试点后的主要终点、误差分布及置信区间精度另行确定。

## 2.11 Statistical analysis

44条登记使用描述性统计。开发集结果作为工程性描述，不提供无偏泛化估计。锁定模拟测试集和真实临床试点分别报告病例级及字段/关系级指标、错误比例和适当置信区间；专家一致性使用适合变量类型的指标 `[VERIFY: 按最终评分量表选择]`。真实病例的独立样本量为病例数，不因一个病例包含多个字段而人为扩大。20条真实病例的统计解释限定为探索性和先导性。

## 2.12 Ethics and data governance

44条去标识化登记的伦理口径；合成语音不含真实患者；20条真实护士录音必须在伦理、知情同意/豁免、去标识化、访问权限和保存期限明确后开展。未经批准的可识别录音、逐字稿或病例内容不得传输给外部API；如使用外部模型，必须记录数据处理边界和批准依据。
# 3 Results

## 3.1 Limited quantity and sparse information in the fixed registry

报告44条人口学、症状类别、文本长度和字段结构。数量有限与质量不足分成两个观察，不混成漏报结论。

## 3.2 Mobile voice-to-report prototype

报告系统组件、数据流、结构化输出、人工审核和禁止自动提交。

## 3.3 Feasibility on 100 clinically grounded simulated nurse-dictation cases

报告100/100成功、运行时间、941项逐字来源、待人工审核和自动提交违规。

## 3.4 Semantic failures despite verbatim source support

报告19/20压力层候选问题及错误类型，突出“来源存在不等于患者事实成立”。该比例是工程审计，不写成临床错误率。

## 3.5 Guardrail revision and development-set regression

报告修订规则、固定20条回归、97项非空事实、14个安全标记和22项离线测试。不得写成独立安全验证。

## 3.6 End-to-end voice and independent evaluation

完成音频和独立测试后报告ASR、字段、关系、语义错误和误差传播。目前为决定性待补结果。

# 4 Discussion

## 4.1 Principal findings

44条登记说明ADE信息收集的现实缺口；100条测试说明LLM结构化整理可运行，但复杂语义需要超越逐字来源检查的控制。

## 4.2 From limited collection to richer nurse narratives

讨论手机录音为何可能承载传统极简登记未保存的信息，但不声称已经提高上报率。

## 4.3 What the LLM contributes

LLM负责整理和映射，不负责创造事实或作临床判断。创新点是受约束的人机报告流程，而不是新模型。

## 4.4 Why source fidelity is insufficient

解释否定、冲突、不确定、模板和指令文本中的字符串同样有来源，因此需要语义状态护栏和人工确认。

## 4.5 Nursing implications

如果端到端语音评价支持，可讨论手机口述作为ADE报告入口的可行性；没有真实护士使用数据时，不讨论节时、减负或采纳效果。

## 4.6 Limitations

单中心44条、数量问题不能直接证明漏报、固定数据字段有限、合成测试数据、开发集调参、工程审计、单模型、当前缺少音频和独立测试、没有真实工作流结局。

## 4.7 Future work

真实护士录音、临床工作流评价、多中心验证和模型漂移监测放未来，不作为当前框架的强制组成。

# 5 Conclusion

结论只回答：本院登记暴露了什么收集问题；手机语音—LLM流程实现到什么程度；100条测试支持什么可行性；复杂语义还存在哪些风险；为什么必须人工审核。

流程具有开发阶段技术可行性，但逐字来源不能替代语义校验和人工审核；端到端语音性能按真实结果限定。

## 10. 当前最关键的开发缺口

不是继续扩充44条，也不是继续增加相似文本，而是完成100条测试数据的语音层：

1. 将现有100条护士口述脚本形成可重复的音频测试集；
2. 固定ASR并生成转写；
3. 建立人工逐字稿；
4. 运行“人工逐字稿→LLM”和“ASR转写→LLM”两条路径；
5. 量化ASR错误对ADE字段、关系和语义安全的影响；
6. 冻结独立于护栏开发的测试部分或新增锁定压力集。

完成这一步，论文才能从“LLM分析合成口述文本”升级为“手机语音—LLM生成ADE报告”的完整可行性研究。
