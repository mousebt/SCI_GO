# 整篇论文框架 v1.1：基于100条真实临床数据的手机语音—LLM辅助ADE报告生成

日期：2026-08-03
状态：当前唯一有效的论文总体框架
作者锁定事实：44条历史ADE登记仅作为项目必要性的基准信息；论文核心研究数据为100条真实临床数据，固定分为80条建模组和20条独立测试组；80条建模组用于建立本地数据字典、标注手册、错误分类、专家裁决标准并开发LLM流程，20条测试组仅在全部规则冻结后用于最终评价；ASR仅作为语音输入的实现环节；FAERS不进入论文。

## 1. 论文定位

本研究不是模型开发论文，也不是语音识别算法论文，而是一项以护理场景为中心的真实临床数据集构建及LLM辅助ADE报告评价研究。研究问题是：护士手机口述中的临床事实能否经受约束的LLM流程转化为准确、完整、可追溯且必须经人工审核的结构化ADE报告草稿。

固定44条历史登记只承担背景职责：它表明现有渠道收集到的ADE记录数量有限、信息不足以支撑高质量报告，因此有必要建立新的真实临床信息采集与报告方式。由于44条记录缺少可供系统评价的完整信息，不对其进行字段级建模、训练、性能评价或与100条真实数据逐例比较。

## 2. 一句话论证

> 针对现有ADE登记信息不足的问题，本研究建立100条真实临床护士语音数据，将80条用于本地评价标准和LLM流程建模、20条作为冻结独立测试组，评价结构化ADE报告草稿的准确性、安全性和专家可接受性，结论限定于单中心、小样本测试组和人工审核条件。

“高质量ADE报告草稿”必须拆解为可测量维度：关键事实准确性、字段完整性、事件关系正确性、来源可追溯性、语义状态正确性、无来源事实、高风险错误和专家可接受性。

## 3. 单一证据链

`44条历史登记提供项目必要性背景 → 建立100条真实临床护士语音数据集 → 80条建模组建立并冻结本地标准与LLM流程 → 20条独立测试组生成报告草稿 → 与专家参考标准比较 → 分析准确性、错误和专家可接受性 → 确定人工审核条件下的边界`

各材料职责：

- 44条历史登记：仅提供项目必要性的基准信息；
- 80条真实临床建模组：建立数据字典、标注手册、错误分类和专家裁决标准，并开发LLM流程；
- 20条真实临床测试组：全部规则冻结后进行独立评价，是LLM性能和安全性结果的唯一来源；
- 本地评价标准：定义什么是正确、完整和可接受的ADE报告草稿；
- LLM与安全护栏：执行结构化整理并限制无来源或语义错误；
- 专家复核：建立参考标准并评价输出，不是系统失败后的补救。

## 4. 研究设计

### Phase 1：历史登记基准

简要报告44条历史登记的时间范围、来源和可用信息边界。该部分只用于说明为什么需要新的真实语音采集与结构化报告流程，不进行复杂统计，不设置独立主表，不把44条称为训练集、验证集或对照组，也不由其推断漏报率、发生率或护士工作质量。

### Phase 2：100条真实临床数据集建立

前瞻性或连续收集100条真实临床护士手机录音及其对应ADE事件资料。

- `[AUTHOR INPUT NEEDED—P01: 明确一条数据的独立单位。建议定义为一个独立ADE事件；同一事件的多段录音合并为一条记录。]`
- `[AUTHOR INPUT NEEDED—P02: 补充研究时间、科室、纳入与排除标准、连续或其他抽样方式，以及同一患者多事件的处理规则。]`
- `[EVIDENCE NEEDED—P03: 100条真实数据的纳入清单、唯一研究编号、去重记录和去标识化审计。]`

每条记录分配唯一研究编号并完成去标识化。

数据集至少保存：原始录音、系统接收的语音转写文本、专家参考结构化报告、LLM结构化报告草稿、来源证据、专家评分、错误编码和最终裁决。ASR属于输入预处理链的一部分，仅记录所用服务、模型版本和运行日期，不设置独立ASR性能终点。

### Phase 3：80条建模组建立标准与开发流程

100条真实数据在模型运行前固定分为80条建模组和20条测试组。80条建模组用于建立本地ADE报告数据字典、标注手册、错误分类和专家裁决规则，并用于Prompt、Schema和语义护栏开发。20条测试组不参与字段定义、专家校准、Prompt设计、护栏修订或阈值选择。

分组应采用可复现的预设方法，并尽可能保持主要事件类型和信息复杂度在两组中的分布。

`[AUTHOR INPUT NEEDED—P04: 确定80:20分组方法，包括分层变量、随机化工具、随机种子、分配执行者和测试组访问控制。]`

在查看20条测试组的LLM输出前，必须冻结数据字典、标注手册、错误代码本、专家裁决规则、模型版本、Prompt、Schema和护栏。

### Phase 4：LLM流程开发与冻结

固定手机语音—LLM处理流程：

`护士手机录音 → 语音转写 → LLM按本地数据字典和Schema整理 → 来源与语义安全检查 → 结构化ADE报告草稿 → 专家复核`

LLM仅从本例口述中提取和组织事实。知识库或报告规则可定义字段含义，但不得补充患者事实。系统不得自动判断因果关系、治疗方案、法定可报告性或最终严重程度，不得自动提交报告。Prompt、Schema和语义护栏只使用80条建模组开发，并在测试前冻结。

### Phase 5：20条独立测试组评价

冻结后一次性运行20条测试组。测试后不得根据这20条的错误修改系统并重新报告为同一独立测试。测试组用于报告主要终点、字段和关系指标、高风险错误、专家可接受性及其不确定性。
## 5. 全文结构

# 1 Introduction

## 1.1 ADE报告为什么需要护士真实叙述

护士接近造影剂给药、症状观察、即时处置和转归过程，手机口述可能比极简登记更完整地承载报告事实。

## 1.2 当前登记方式的现实不足

以44条历史登记作为简短基准，说明现有收集结果不足以形成完整、可复核的ADE报告。该部分只建立研究必要性，不展开病例特征分析。

## 1.3 LLM辅助报告的机会与风险

LLM可把自由叙述映射为结构化字段，但可能发生遗漏、无来源补充、关系错误以及否定、冲突和不确定信息误判，因此必须建立本地专家参考标准和人工审核边界。

## 1.4 研究目的

建立100条真实临床护士语音数据集及本地评价标准，并评价手机语音—LLM流程生成结构化ADE报告草稿的准确性、安全性和专家可接受性。

# 2 Methods

## 2.1 Study design and setting

说明单中心研究设计、研究场景、研究时间和总体流程。研究由历史基准、真实临床数据集建立、本地标准制定、LLM处理和专家评价构成。

## 2.2 Historical registry as the rationale baseline

只报告44条历史登记的来源、时间范围及其作为项目必要性背景的用途。明确其信息不足，不能用于训练、标注标准建立或模型验证。

## 2.3 Construction of the 100-case real-world clinical dataset

报告100条真实临床记录的招募/纳入方式、录音场景、事件单位、去重规则、去标识化、数据存储和质量控制。

`[AUTHOR INPUT NEEDED—P01: 明确100条是否对应100个独立ADE事件；若同一事件存在多段录音，规定合并方法；若同一患者发生多个事件，规定独立性判断。]`

## 2.4 Mobile voice-to-structured-report workflow

描述录音、语音转写、LLM、JSON Schema、来源检查、语义护栏、缺失/冲突提示和人工审核。ASR只作为语音输入实现步骤，记录版本和参数，不设置独立ASR性能研究。

## 2.5 Development of the local data dictionary

仅使用80条建模组和ADE报告任务定义患者/报告者、疑似产品与给药、事件、时间、生命体征、处置、升级、转归、随访、字段关系、缺失和不确定状态。每个字段记录定义、允许值、来源要求、缺失编码和禁止推断规则；在20条测试组启封前冻结版本。

## 2.6 Annotation manual and expert reference standard

专家在查看LLM正式评价输出前，依据预先允许的临床材料独立形成参考报告。

- `[AUTHOR INPUT NEEDED—P05: 明确专家可查看的材料范围——原始录音、语音转写、护理记录、医嘱、用药记录、生命体征和随访资料中允许哪些作为参考来源。]`
- `[AUTHOR INPUT NEEDED—P06: 补充两名独立标注专家和第三名裁决专家的专业背景、资历要求、培训与校准流程、盲法及分歧处理规则。]`
- `[EVIDENCE NEEDED—P07: 保存双专家逐例标注表、分歧记录、第三专家裁决表和最终参考报告。]`

## 2.7 Error taxonomy and adjudication rules

预先定义：字段遗漏、事实错误、无来源增加、关系错误、否定错误、冲突处理错误、不确定性升级、时间错误及其他语义错误。将错误分为一般错误和可能影响临床理解或后续报告的高风险错误。数据字典、标注手册、错误分类和裁决规则必须在冻结评价开始前版本锁定。

## 2.8 Dataset partitioning and leakage control

100条数据固定按80:20划分。80条建模组允许用于专家校准、数据字典和标注手册修订以及LLM流程开发；20条测试组仅用于最终评价。报告分组发生时间、分层或随机方法、随机种子、执行者、组间基本特征以及测试组访问控制。任何基于20条测试结果进行的后续修订必须进入新版本研究，不能回写本次测试。

## 2.9 LLM evaluation and outcome measures

LLM主要性能只在20条测试组中评价。

`[AUTHOR INPUT NEEDED—P08: 在测试组启封前确定唯一主要终点。当前候选为“专家裁决后无需修改或仅需轻微修改即可使用的病例比例”；关键安全性指标候选为“至少出现一个高风险错误的病例比例”。]`

80条建模组结果仅用于描述开发过程，不与测试组合并。次要指标包括：

- 字段级precision、recall和F1；
- 关键事实准确性和遗漏；
- 产品—事件—时间—处置—转归关系正确性；
- 来源可追溯性与无来源事实；
- 各类错误和高风险错误的病例数及比例；
- 专家判定为可直接接受、修改后接受或不可接受的比例；
- 系统运行失败及人工审核状态。

## 2.10 Statistical analysis

44条历史登记仅作描述性背景。80条建模组用于描述数据字典、错误分类和流程开发，不提供独立性能估计。20条测试组按病例级报告主要终点、错误数和精确95%置信区间；字段/关系级指标作为次要分析。

`[AUTHOR INPUT NEEDED—P09: 根据最终评分量表选择专家一致性指标——名义分类用Cohen's kappa，有序分类用加权kappa，连续评分用ICC；同时确定置信区间计算方法和统计软件版本。]`

病例是独立样本单位，不能以同一病例中的多个字段扩大样本量。由于测试组仅20例，1例对应5个百分点，所有性能结论均按探索性小样本评价解释。

## 2.11 Ethics and data governance

报告伦理批准、知情同意或豁免、患者与护士隐私、录音去标识化、访问权限、保存期限和删除规则。

`[EVIDENCE NEEDED—P10: 伦理批准号、知情同意或豁免依据、隐私与去标识化方案、数据访问名单、保存期限、删除规则，以及外部LLM数据处理批准文件。]`

未经批准的可识别录音或病例内容不得发送至外部API；如使用外部LLM，必须说明数据处理协议、传输区域、日志保留和机构批准依据。

# 4 Discussion

## 4.1 Principal findings

围绕100条真实临床数据回答：本地标准是否可建立、LLM草稿达到什么表现、主要错误在哪里、人工审核为何仍然必要。

## 4.2 Contribution to nursing ADE reporting

讨论手机口述作为信息采集入口和LLM作为结构化整理工具的临床意义，不把研究写成新模型或ASR算法开发。

## 4.3 Meaning of the expert reference standard

解释本地数据字典和专家裁决如何使“高质量报告”从主观评价转化为可重复的操作标准，同时承认其单中心边界。

## 4.4 Safety and human oversight

讨论来源追溯、语义错误、高风险错误和人工审核条件；不声称系统可自动替代护士、药师或监管人员。

## 4.5 Limitations

单中心、100例总体和20例测试组导致的估计不精确、建模组与测试组来自同一中心、专家数量、单一LLM、真实录音隐私、病例谱限制，以及没有评价长期上报率、时间成本或患者结局。

## 4.6 Future work

多中心外部验证、扩大病例谱、前瞻性工作流效果和模型漂移监测放入未来研究，不作为当前论文已完成内容。

# 5 Conclusion

结论只回答：44条历史登记为什么使项目必要；100条真实数据建立了什么本地标准；LLM在真实临床口述中达到什么表现、存在哪些错误；系统必须在什么人工审核条件下使用。

| 手机语音—LLM流程 | ASR只作为输入实现步骤，不作为独立评价模块 |
| 结构化ADE报告草稿 | 不称自动报告或最终临床报告 |
| 高风险错误 | 按冻结错误代码本定义，不凭研究者事后判断 |
