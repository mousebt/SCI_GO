# 正式稿撰写规范：护理不良事件报告规格与叙述性输入辅助原型

日期：2026-08-03  
状态：已被`project-development-framework-v1.0-2026-08-03.md`取代；仅保留为历史讨论记录  
适用论文：`nonionic-contrast-faers-nursing`  
结构决策：FAERS不是本稿成立的必要证据，完全退出题目、摘要、关键词、正文、主图表和补充材料论证链；既有FAERS成果保留在项目中，但不得自动回填本稿。

## 1. 论文身份

### 1.1 研究类型

多阶段、证据知情的护理信息学开发与形成性评价研究。研究对象不是某个LLM模型，而是：

1. 面向护士的造影剂不良事件报告规格；
2. 将叙述性输入整理为结构化、来源可追溯且必须人工审核的报告草稿的辅助流程；
3. 该流程的内容准确性、语义安全性和护理工作流可用性。

### 1.2 当前正式题目

中文：**造影剂不良事件护士报告规格及叙述性输入辅助原型的开发与形成性评价**

英文：**Development and Formative Evaluation of an Adverse Event Reporting Specification and Narrative-Input Assistant for Nurses Following Iodinated Contrast Administration**

只有完成固定ASR、真实音频和端到端误差传播评价后，才可将“叙述性输入”改为“语音辅助”。

### 1.3 一句话论证

> 本研究依据正式报告要求、标准术语、造影剂临床安全指南及临床利益相关者意见，开发面向护士的造影剂不良事件报告规格，并通过独立标注语料和护士任务测试，形成性评价叙述性输入辅助原型的内容准确性、语义安全性和工作流可用性。

在独立评价和护士任务测试完成前，后半句只能写为研究目的，不得写成已获得结论。

### 1.4 单一论证链

`护理报告任务及信息转换负担 → 规范性证据形成初始报告规格 → 临床利益相关者参与式修订 → 受约束的叙述性输入辅助原型 → 开发阶段错误暴露与护栏修订 → 独立准确性/安全性评价 → 护士形成性可用性评价`

任何不能进入这条链的材料不进入正文。

## 2. 范围契约

### 2.1 必须进入本稿

- ICSR/E2B或适用正式报告要求所定义的最低信息域；
- MedDRA或适用标准术语原则；
- ACR、ESUR或适用造影剂安全指南中与记录内容有关的要求；
- 报告字段及产品—事件—时间—处置—转归关系；
- 否定、冲突、不确定、缺失、模板、假设和指令性文本的状态表达；
- 临床利益相关者对字段必要性、可获得性、清晰度和工作流适配性的修订；
- LLM、来源校验、语义护栏和人工确认构成的辅助流程；
- 开发集错误发现、独立测试和护士任务测试。

### 2.2 默认不进入本稿

- FAERS提取、信号检测、PT/SOC、TTO、Weibull和报告者构成结果；
- 四种造影剂的信号或安全性比较；
- 与正式报告规格没有直接关系的药物警戒数据库方法；
- API限流、重试和并发控制等运维细节；
- 大段模型架构、Prompt工程或平台开发说明；
- 未完成伦理、来源和口径核验的39/44例本院登记结果；
- 未经验证的效率、负担、上报率、护理质量或患者结局改善主张。

### 2.3 本院材料的使用规则

本院材料只有在研究期、来源、39/44口径、去重、伦理和编码可靠性全部锁定后，才可作为“本地报告需求形成性输入”。除非预先设计为独立文档质量审计并完成双人编码，否则不单列为主要结果，也不用于推断漏报或发生率。

### 2.4 既有FAERS材料的处理

不删除、不降格、不否定其技术有效性；统一标记为“当前稿件范围外的既有项目资产”。后续只有在形成独立且证据充分的研究问题时才重新评估，不以“已有数据不能浪费”为理由写回本文。

## 3. 核心研究问题

1. 基于正式报告要求、标准术语、临床指南和利益相关者意见，护士造影剂不良事件报告应包含哪些字段、关系和语义状态？
2. 这些要求能否被实现为来源可追溯、带语义安全控制且必须人工审核的结构化报告草稿流程？
3. 在独立锁定测试集中，该流程对字段、关系和语义状态的准确性及高风险错误表现如何？
4. 护士在代表性任务中使用该流程时，其完成时间、人工修改量、错误发现和形成性可用性如何？
5. 仅当完成音频评价时：ASR错误如何传播至字段、关系和语义状态？

## 4. 研究阶段与证据要求

### Phase 1：初始报告规格开发

输入：正式报告要求、标准术语和临床指南。  
输出：初始字段清单、关系模型、状态定义和证据—要求映射。  
必须报告：来源版本、映射规则、纳入/排除规则、初始字段数及类别。  
禁止：把研究团队自行设计的字段写成公认标准。

### Phase 2：参与式修订

输入：初始规格、低保真或可交互原型、代表性任务。  
参与者：放射科护士以及与报告审核或处置相关的人员；角色按实际纳入报告。  
输出：删除、合并、重命名、新增和责任归属的完整轨迹及最终规格。  
必须报告：招募、角色、轮次、评价维度、分歧处理和停止依据。  
禁止：未采用正式Delphi时称“专家共识”；未测量时称“内容效度已验证”。

### Phase 3：原型实现与开发集修订

输入：叙述文本；若使用语音，区分人工逐字稿与ASR转写。  
流程：`叙述输入 → Schema提取 → 来源定位 → 语义状态控制 → 缺失/冲突提示 → 护士确认 → 报告草稿`。  
必须保留：原始输入、来源位置、安全标记、人工审核状态和版本信息。  
禁止：自动判断因果、严重性、可报告性或治疗；禁止自动提交。

### Phase 4：独立准确性与安全性评价

必须使用未参与Prompt、规则或护栏开发的锁定测试集。  
至少两名合格评价者依据标注手册建立字段、关系和语义状态参考标准，并记录分歧裁决。  
主要指标应从字段级或关系级precision、recall、F1及高风险语义错误中预先指定。  
次要指标可包括幻觉、遗漏、否定泄漏、冲突错误确定、模板/假设泄漏、人工审核触发和置信区间。  
现有100条80/20语料及固定20条压力集均为开发材料，不得重新命名为独立验证集。

### Phase 5：护士形成性可用性评价

使用代表性报告任务，记录客观完成时间、人工修改量、未纠正错误、提示理解和任务完成情况；量表可使用经核验的SUS或MAUQ，并以访谈解释评分。  
禁止用主观“感觉更快”替代时间数据，禁止从形成性评价推断临床上报率或患者结局改善。

### 可选Phase 6：语音与ASR评价

只有固定ASR模型、多说话者音频、人工逐字稿和误差传播分析均完成时，语音才可成为实证贡献。应报告字符或混合错误率、药名/剂量/时间错误，以及ASR输入与人工逐字稿输入之间的下游差异。

## 5. 章节契约

### 5.1 Introduction

目的：建立护理报告任务、信息转换负担和安全受控辅助的必要性。  
允许主张：护士处于事件观察、处置、记录和报告信息形成的重要位置；自由叙述到标准报告存在结构和关系转换问题；无约束LLM存在语义安全风险。  
禁止主张：本院存在漏报；系统已经节省时间；FAERS提示证明某事件应优先报告；“首次”“领先”“全面”等未经系统检索支持的创新性表述。  
固定四段：临床相关性 → 现有报告问题 → 数字辅助机会与风险 → 研究目的。

### 5.2 Methods

目的：让读者复现规格形成、原型实现和评价过程。  
顺序：研究设计 → 规范性证据来源 → 初始规格 → 参与式修订 → 最终规格 → 原型与安全边界 → 开发材料 → 独立评价 → 护士评价 → 统计 → 伦理治理。  
禁止：把计划中的参与式或独立评价写成已经实施；用产品/API运维细节替代可复现方法。

### 5.3 Results

目的：按研究阶段报告观察结果，不解释意义。  
顺序：规格形成 → 利益相关者修改轨迹 → 最终规格和原型 → 开发错误与护栏修订 → 独立准确性/安全性 → 护士任务和可用性 → 可选语音结果。  
现有100/100、941项逐字来源、19/20候选问题、固定20条回归和22项离线测试只能进入“开发错误与护栏修订”。  
禁止：以请求成功率代替临床准确性；以固定开发集回归代替独立安全验证；设置“待完成的结果”小节。

### 5.4 Discussion

目的：解释报告规格、语义安全和人工责任的意义。  
固定逻辑：主要发现 → 内容与关系规格先于技术实现 → 来源存在不等于患者事实 → LLM仅生成待审核草稿 → 护理工作流意义 → 局限性与下一阶段。  
禁止：重新复述全部技术结果；将形成性可用性升级为临床有效性；讨论FAERS信号。

### 5.5 Conclusion

只回答三个问题：形成了什么报告规格；独立评价支持到什么程度；人工审核和适用边界是什么。  
如果独立测试或护士评价未完成，结论必须停留在“开发完成/开发集观察”，不得写“准确、有效、可用、提高效率”。

### 5.6 Abstract与Title

最后撰写。摘要中的每个结果数字必须来自正式Results；不得把计划方法或缺失证据写入结果。题目只包含已经形成实证结果的组成部分。

## 6. 主张与语言纪律

- “开发”用于规格或原型确已形成；“验证”仅用于预设、独立且有参考标准的评价。
- “形成性评价”不等于临床有效性评价。
- “来源可追溯”只表示输出可定位到输入，不表示语义正确。
- “人工审核”是系统组成部分，不是失败后的补救性描述。
- `adverse event (AE)`不自动替换为`adverse drug reaction (ADR)`；除非存在正式因果判断。
- 使用“叙述性输入辅助原型”；没有完整音频证据时不使用“语音报告系统”。
- 使用“报告规格”；在完成参与式修订和适当验证前不称“验证框架”或“标准”。
- 所有未获得结果标记`[EVIDENCE NEEDED]`；待核验文献或版本标记`[VERIFY]`。

## 7. 正式稿准入条件

### Gate A：可以开始写正式Results

- 正式报告规范、MedDRA和临床指南来源及版本已核验；
- 最终字段、关系、状态定义和修改轨迹已锁定；
- 参与式审核方法与伦理路径已确认；
- 原型、Schema、Prompt、规则和模型版本已冻结；
- 开发集和独立测试集完全隔离；
- 标注手册、评价者和裁决规则已锁定。

### Gate B：可以使用“形成性评价”题目

- 独立测试已完成并报告预设指标；
- 护士任务测试已完成；
- 结果包含客观指标而不只是主观意见；
- 高风险错误和未纠正错误已逐例审计。

### Gate C：可以使用“语音辅助”题目

- 固定ASR和音频数据已经评价；
- 有人工逐字稿参考；
- 报告ASR本身及下游误差传播；
- 伦理、知情同意、隐私和外部模型治理已确认。

任一Gate未通过时，缩小题目和结论，不以流畅文字掩盖证据缺口。

## 9. 撰写顺序

1. 锁定研究范围和上述Gate；
2. 完成参与式审核、独立测试和护士任务评价；
3. 先写Results；
4. 根据真实结果锁定一句话结论；
5. 写Introduction与Conclusion；
6. 写Discussion；
7. 补齐Methods；
8. 最后写Title与Abstract；
9. 执行主张—证据、术语、引用、统计和全文一致性审计。

- 临床利益相关者参与式审核及修改轨迹；
