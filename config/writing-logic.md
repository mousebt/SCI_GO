# 底层写作逻辑（全局唯一来源）

版本：1.0.0  
生效范围：所有新论文；单篇论文只能在 `paper.yaml` 中声明有限覆盖。

## 1. 读者问题顺序

论文应依次回答：

1. 相关性：这项工作与读者有什么关系？
2. 新意：新增了什么可靠认识或能力？
3. 可信度：证据是否足以支持主张？
4. 可复用性：方法、数据和边界是否清楚？
5. 意义与边界：结果意味着什么，又不能推出什么？

## 2. 一句话论证

所有章节必须服务于同一句话：

> 在【系统/问题】中，我们采用【方法】显示【有边界的推进】，由【关键证据】支持，适用边界为【边界】。

无法写清这句话时，不进入完整正文撰写。

## 3. 研究论文论证链

`领域需求 → 未解决瓶颈 → 本文动作 → 决定性证据 → 更广意义 → 适用边界`

任何缺环都必须显式标为待补，不能靠流畅语言掩盖。

## 4. 默认撰写顺序

`结果 → 引言与结论 → 标题 → 讨论 → 方法 → 作者贡献 → 摘要`

这不是最终章节顺序，而是写作顺序。引言应围绕真实结果建立，不应预先制造结果无法填补的空白。

## 5. 证据纪律

- 每个主要主张必须能定位到图、表、统计、数据集、比较或已核实文献。
- `show/demonstrate` 只用于直接而充分的证据；间接证据使用 `suggest/indicate/is consistent with`。
- 禁止未经核实的 `first`、`unique`、`unprecedented`、`comprehensive` 等表述。
- 结果描述观察；讨论解释意义。相关性不能自动升级为因果机制。
- 引用必须来自实际阅读和核验的原始来源；不可生成占位 DOI 或虚构文献。

## 6. 一段一职能

每段只承担一种主要职能：背景、缺口、方法、结果、比较、机制、意义或局限。首句给出该段主张，后续句子与前句有明确逻辑关系。

## 7. 术语和修改纪律

- 写作前建立术语账本；一个概念只保留一个规范名称。
- 修订采用局部修改，保留未被质疑的内容。
- 结构重排、核心主张变化或术语重命名必须记录在变更日志中。

## 8. 人机边界

AI 可以辅助结构、表达、翻译、核查和备选方案；作者必须确认核心论证、数据解释、引用、统计、图像处理和最终稿。敏感未发表材料不得上传到未经批准的外部服务。

## 修改本文件

底层逻辑的变更必须：提出变更理由 → 在至少一个论文中验证 → 记录影响范围 → 人工批准 → 提升次版本号 → 写入 `knowledge/change-log.md`。单个项目的特殊做法优先放入该论文 `paper.yaml`，不要立即全局化。
