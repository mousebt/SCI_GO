# 批准与决策日志

本目录保存所有由助手提出、需要用户批准后才能执行的实质性计划方案。目标是让未来能够回答：当时知道什么、为什么提出该方案、用户批准了什么、最后实际做了什么。

## 必须记录的情况

- 论文核心主张、研究边界或目标期刊的选择。
- 对已有稿件进行大规模重构、拆分或合并。
- 删除、覆盖、迁移尚未验证的研究材料。
- 使用外部服务处理未发表或敏感材料。
- 修改全局写作逻辑、知识提升规则或项目目录架构。
- 任何包含多个选项、需要用户作出实质判断后才能继续的计划。

单纯的只读检查、常规局部修改和系统沙箱的机械执行授权，不作为“计划方案”单独记录；如果技术授权同时包含实质性决策，则必须记录。

## 工作顺序

1. 在向用户提出批准请求之前创建 `pending` 日志。
2. 日志必须包含相关对话原文、当时已知事实、假设、选项、计划、影响范围及原样批准问题。
3. 向用户发问时附带日志 ID。
4. 用户回复后，在同一日志末尾追加原始回复与处理结果，不覆盖原始方案。
5. 若方案发生实质改变，把旧方案标记为 `revised`，新建一个日志并相互链接。
6. 方案执行完成后记录实际变更和对应 Git 提交。

## 文件结构

- `approval-index.csv`：全局索引。
- `approvals/YYYY/MM/`：一项批准方案一个 Markdown 文件。
- `governance/`：日志制度本身及其他项目级治理决定。

日志只保存与决策相关的对话，不复制无关聊天或完整敏感数据。论文级日志通过 `paper_id` 关联到 `papers/<paper_id>/`。
